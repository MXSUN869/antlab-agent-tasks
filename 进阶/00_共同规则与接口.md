# 共同规则与验收边界

## 决策责任

关键决策包括研究命题、对照/指标、修复方案、结果解释和是否继续。至少保留三项对最终结论有实际影响的决定（基础已有记录可引用，但进阶新增决定须补充），写出：本人当时判断、替代方案、可否定观察、AI/他人影响、证据链接、最终决定。没有事前记录就注明事后整理，禁止补造时间线。

至少有一条证据使你检验了原判断；AI生成测试也要检查其是否能抓住错误实现。核对一条论文原文、一个实际请求和一次失败，是比大量工具调用记录更有价值的证据。

## 最小全栈闭环

输入问题/主张与资料范围 → 后端实际处理 → 结构化结果/状态 → 原始证据回溯 → 同一请求日志。至少能比较基线与改进/修复/替代路线。界面简洁即可，视频或静态截图不能代替闭环。

接口路径自由，README给出映射。请求至少含query或claim、doc_ids、snapshot、mode；结果至少含request_id、实际使用的文档/快照、answer或claim、evidence、locator_status、support_status、judgment_source、elapsed_ms、run_kind。每项证据有doc_id、snapshot、稳定block_id、原文、page；使用坐标时说明坐标系。不适用字段写null和原因。

- locator_status：valid / invalid / absent；表示引用存在且属于当前请求实际资料范围。
- support_status：supported / contradicted / insufficient / not_checked。必须说明检查的是哪条主张；引用可定位不等于语义支持。未实现语义检查时用not_checked。
- judgment_source：rule / model / human / unverified。人工评测标签不得伪装为系统输出，模型自评不能作为唯一金标准。
- run_kind：live_api / offline_replay / dry_run / local_rule。成本、延迟按类型分别报告。

对未知文档、错误快照、无证据和执行失败明确返回；禁止硬编码题号、金标签或答案。运行推理逻辑不得读取开发答案文件；开发答案只用于调试评估。

## 实验契约

先写一个主假设及至少一个竞争解释；固定数据版本、主指标、失败分母、主轮次、参数、停止条件。开发与评测分开；配置冻结后运行评测，之后改动只能报告为追加探索。输入公开不代表真正盲测；阅读、筛选或调参的接触情况如实披露。

比较须配对任务。多调用、多输出长度、不同模型或更多上下文带来的收益要单列；不能直接归因架构。至少做一个能区分解释的干预/消融或负对照，以及一个任务等价变体（文档/证据ID重映射、等价措辞、输入顺序等）。变体不是要求随机生成文本，须论证语义和证据关系未变；有排序并列时允许等价差异。

报告逐例结果与失败，禁止只取最好一次、删掉拒答和错误。小样本不支持总体胜率或显著性宣称；重复调用不等于更多独立问题。引用率高但全是空泛拒答，需要同时看覆盖/可用性。

至少一个指标针对用户任务质量，另一个针对代价或使用负担。只测客户端完整请求耗时；B离线重放毫秒值表示样机运行，不代表LLM耗时。Token可留空；可复跑配置保留在代码或运行日志中。

源码基点、本人改动和报告结果的复算入口，统一写在《05_提交与报告格式》所述位置。

AI使用声明不能替代实验依据。实际实验的原始输入、响应、失败、首次/重试以及基线—改进配对仍须提交；三项关键决策及其中的AI影响仍须保留。评委只检查基线与改进是否使用声明一致的设置，以及配置是否能从代码或运行日志定位。

## 公布的复核方式

截止后评委可使用未公开的同范围新样例及等价变体，对最终登记的commit检查实际选段、模型输入和数据依赖；发现无法解释的差异时再做定向模型复跑。此核查沿用现有评分维度，不增加一周作业。

评委可检查启动、抽样回放日志、核对原文，也可改变已公告的文档ID、证据ID、顺序、版本或等价措辞后运行你的测试。需要核验本人贡献与判断时，会请你先解释并预测，再查看代码或运行结果。

如果报告称某项做法有新意，请对照已有方法说明它带来了什么新认识、边界或取舍。实际结果没有改善时，分析原因及适用条件。
