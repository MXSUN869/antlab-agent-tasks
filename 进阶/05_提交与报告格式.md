若直接修改开源项目，在README写明上游地址、修改前的源码基点commit、最终commit，以及查看本人diff的命令或补丁。若只把库作为依赖，写明锁定版本和本人编写的适配文件。题包骨架可用题包版本与文件校验值作为源码基点。Git历史帮助评委理解过程，提交次数不作为排名依据。

建议目录：
```
GitHub 仓库根目录/
  README.md                 # 启动、测试、基本环境、完成/未完成表
  report.pdf 或 report.md    # 一份整合报告，建议约6页，证据附录不限
  src/ 或项目源码/
  tests/
  configs/                  # 模型、参数、数据hash；无密钥
  runs/                     # 基础与进阶分组，实际输入、原始输出、失败
  results/                  # 逐例评价与汇总，可由脚本复算
  decisions.md              # 决策时间线、证据链接、AI影响
  declaration.md            # AI/他人/复用/未完成声明；不含密钥或Endpoint
```

基础与进阶共用一份整合报告。建议约6页；原始结果和证据索引可放附录。较大的结果文件可放在 GitHub Release，并在仓库 README 中给出固定下载链接及校验值。

## 报告固定栏目

1. **完成概览**：选择题号；做成什么、没做成什么；最值得核验的三个结果及路径。
2. **阅读到命题**：原论文的一项命题、条件与原文位置；本题输入/输出、范围变化；至少两项学习材料知识如何改变决定。
3. **实验设计**：假设/竞争解释/自变量/因变量/控制/基线/指标/预测/否定条件；开发与评测接触说明；冻结时间与代码/数据/配置hash。
4. **实现与复现**：一条全栈请求链；关键模块；用到AI/开源哪些部分；一次实际请求能否从界面追到日志和原文。
5. **结果与诊断**：基础逐题汇总引用附件；进阶同任务配对表；所有失败/未检查；代价；判别实验、反例、变体；结论及替代解释。
6. **决定与未来**：保留/修改/停止；两个相关系统比较；一项应用—推理联合验证问题；长期维护最关键约束。C按题目补三个阶段的证据门槛。

每张结果表和图在标题或表下注明汇总文件、复算命令及所用run ID。评委会抽取一个数字，从汇总找到对应运行的实际输入、原始响应和配置，再离线复算。文字结论链接到具体运行或原文位置，并说明判断依据。

仓库保留实验的实际输入、原始响应、失败、首次/重试、客户端时间和初始方案与改进方案的配对结果。可复跑配置放在代码或运行日志中；AI声明填写统一五项，Token可留空。提交前检查并移除API密钥、Endpoint、私人账号信息和本地配置。

| E2 | 论文命题及原文位置 |
| E3 | 基线/改进或两路线的逐例原始结果 |
| E4 | 竞争解释和有辨别力的检查 |
| E5 | 反例/变体/回归与未解边界 |
| E6 | 三项决定及AI影响 |
| E7 | 可定位配置、统一AI声明；简历在收集表中 |

README给出启动、测试和复算命令，标明会产生模型费用的命令；评审默认使用已有结果离线回放。重放与真实调用分别标识。资料无法共享时说明原因并提供可复核的替代材料或承认该部分无法复核。
