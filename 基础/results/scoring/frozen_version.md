# 代码版本时间线与「冻结版本」的界定

## 为什么必须写这一页

题目要求「记录冻结时的代码、数据与配置版本」，并要求「确认实际 messages 和段落 ID、原文、
顺序与清单一致」。逐条核对 116 条付费记录的 `student_sha256` 后发现：

> **40 次正式主结果与 41 次所谓「重试」使用的不是同一版 `student.py`；
> 41 次重试的实际 messages 与主结果逐条都不同。**

因此那 41 次不能当作「同条件重复测量」，必须改标为**追加探索**。
本页保留完整的时间线与证据，供评委核对，也避免这个差别被当成同一条件的重复。

## 具体改了什么

对比同一用例（T06 / R0 / baseline）在冻结版与 10-14 版本的 **实际 messages**：

- `selected_passage_ids` **完全相同** → 改版没有改变 `improve()` 的选段与排序行为。
- **system 消息**（204 → 210 字符量级）与 **user 消息**（2528 → 2530 字符）**都发生了变化**。
  逐字符 diff 显示这是一次**提示词改写**，例如：

| 位置 | 冻结版（`893e1e16…`） | 10-14 版（`3a8c56bb…`） |
|---|---|---|
| system 第 1 条 | 「只能使用用户提供的资料回答，**不能凭空补充事实**。」 | 「只能使用用户提供的资料回答。**不允许使用外部知识**。」 |
| system 规则条数 | 5 条 | 6 条（拆出「不要输出推理过程」） |
| system 末行 | 「输出必须是合法 JSON，**不要输出 JSON 之外的内容**。」 | 「只输出合法 JSON。」 |
| user 末行 | 「请**根据以上资料回答**问题。」 | 「请**直接输出 JSON 答案**。」 |

- 40 条主结果的 system 消息**完全一致**（1 种模板），user 消息在把问题原文与段落内容
  替换为占位符后收敛为 **2 种模板**（7 段条件与 K 的 2 段条件各一种）。
  逐字模板已导出为 `frozen_prompt_893e1e16.txt`。

## 对已有结论的影响

**不受影响的结论**

1. **输出截断的机制**。13 条正文为空的记录全部满足
   `completion_tokens = reasoning_tokens = max_tokens = 1024` 且 `finish_reason = length`。
   这是 `usage` 字段里的直接读数，与提示词措辞无关。
2. **40 次主结果的构成与判分**。R0/R1/R2/K 各 8 次 + R0 改进 8 次，全部来自冻结版本，
   代码哈希、数据哈希、模型与参数在这 40 条内完全一致
   （`student_sha256` 单一取值 `893e1e16e134…`，`data_sha256` 单一取值
   `c37cda40ada89a18…`，`model` 与 `parameters` 单一取值）。

**必须修改的结论**

1. 原先把 41 次记录称为「同参数重试」并据此说「同一请求会随机地在成功与截断之间翻转」，
   **这个说法不成立**：那 41 次用的是**改后的提示词**，与主结果不是同一输入。
   正确表述见 `failure_index.md` 第四节：它们说明的是
   **截断在另一个提示词版本下依然出现（5/41）**，属于跨版本的稳健性观察，
   而不是同条件的重复测量。
2. 「把 `max_tokens` 从 1024 降到 512 会让截断点前移」这一条同时伴随提示词改写
   （该记录的哈希是 `0521934d…`，与前后两次都不同），因此只能作为**提示性证据**，
   不能作为单独的自然实验。`failure_index.md` 第三节已按此改写。

## 冻结版本的输入是否还能复现

- **能，且不需要冻结版的源码**：每条主结果的实际模型输入已逐字保存在
  `runs/<run_id>.json` 的 `messages` 字段。评委若要重放，直接取该字段即可，
  不需要重新运行 `student.py`。
- `frozen_prompt_893e1e16.txt` 给出该版本的提示词模板，可用于核对
  「当时发给模型的是什么」。
- **`improve()` 的行为也已固定**：每条记录都保存了 `original_passage_ids` 与
  `selected_passage_ids`，改进版的排序结果可以直接比对，不需要冻结版源码。
- **未能保留的**：冻结版 `student.py` 的源码本身（`893e1e16…`）没有被单独归档，
  因此无法用它重新生成 prompts。这是本次交付的一个已知缺口，如实记录；
  上面三条使这个缺口不影响对 40 条主结果的核查与重放。
