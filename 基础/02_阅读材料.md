# 阅读入口与知识提要



## 主论文（必读相关部分）

Nelson F. Liu等，Lost in the Middle: How Language Models Use Long Contexts，2023预印本、TACL 2024。
- 正文 https://arxiv.org/html/2307.03172v3
- PDF https://arxiv.org/pdf/2307.03172
- 作者代码/数据 https://github.com/nelson-liu/lost-in-the-middle

阅读第2节实验、第4节相关解释、第5节更多上下文及结论。理解实验条件而非抄出U形结论。无需安装作者整个仓库，本次中文模拟数据、任务和API与原实验不同。下列知识提要为本考核自编，不是论文原文。

## 必要概念

上下文窗口是模型服务可接受的上下文容量，不保证它能有效利用所有内容。Token是模型分词单位，中文字符数不能直接当Token；聊天模板和服务端包装也可能消耗上下文。

Prefill处理输入并建立后续生成需要的内部状态；Decode逐步生成。KV Cache与这些过程有关，但闭源API客户端不能仅凭总耗时反推出服务端缓存命中或某个阶段耗时。提供请求的模型版本/参数与实际日志比猜测GPU型号更有价值。

完整请求耗时是客户端发出请求到读完整个响应的时间，可能含网络、排队、服务处理和输出传输。首Token延迟必须先定义计时点、流式事件和“答案Token”，不能把收到HTTP头或进度消息当答案首Token。本骨架仅测非流式完整耗时。

准确率必须定义样本单位与分母。每题四条件是配对观察，不是四个独立新题。8题的变化可能由任务构成、随机性和服务漂移造成，观察差异不自动构成统计或机制证明。

R0/R1/R2使用相同段落集合，K只提供两段。比较K与全文时同时考虑资料量与选择方法；比较三种全文顺序时核对实际消息和输出。

API usage可能提供输入、输出、缓存或推理Token；只按实际字段理解，Token量级可选且缺失无需解释。有效参数以实际代码/运行配置为准，不要让AI虚构参数或默认值。

## 项目认识：选择一个公开系统

1. Semantic Reader：研究论文 https://arxiv.org/abs/2303.14334 ；阅读界面 https://openreader.semanticscholar.org/ 。观察文档内的定位与阅读交互。
2. ALCE：研究论文 https://aclanthology.org/2023.emnlp-main.398.pdf ；代码 https://github.com/princeton-nlp/ALCE 。观察答案正确与引文支持怎样分开核查。

可拓展：Self-Refine https://arxiv.org/abs/2303.17651 与自校正边界 https://arxiv.org/abs/2310.01798 。两者条件不同，不凭标题判定互相推翻。拓展不要求额外复现。

## 项目背景（供本题使用）

团队正在开发文档阅读与信息核验工具，现阶段关注资料理解、原文定位、阅读交互和可维护交付。本题用实验帮助判断怎样组织资料、核查引用，以及下一步该验证什么。视觉定位、多模块协作与推理服务效率都可以作为后续问题讨论。
